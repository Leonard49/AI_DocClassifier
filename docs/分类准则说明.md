# AI DocClassifier 分类准则说明

> 版本：`feature/arch-data-dir-cleanup`（贴表双路径、展示标题重命名、源→TARGET 刷新、控制台分组）  
> 更新日期：2026-08-13  
> 依据：QT-SOP-PM-048E（项目名/模组命名规则）+ 现有标签树  
> 相关：[QUICK_START.md](QUICK_START.md) · [CONSOLE.md](CONSOLE.md) · **[BRANCHES.md](BRANCHES.md)**（迭代优化日志）

本文说明优化后的文档分类规则、产品线判定方法、Others 质量控制、目标目录单层节点超限时的分卷策略，以及元数据归纳方式。

---

## 1. 分类目标

将飞书知识库中的**技术叶子文档**复制到目标目录下的标签树路径中，例如：

```
Cellular -> Network -> LTE Network
Smart -> BSP -> USB
GNSS -> GNSS功能原理 -> RTK
```

并尽量避免落入顶层 `Others`。

下列类型**不分类、不复制**（输出 `SKIP:…`）：

| 类型 | 典型标题/路径特征 |
|------|-------------------|
| 周报 | Weekly Report、周报 |
| 日报 | Daily Report、日报 |
| 会议纪要 | Meeting Minutes、会议纪要 |
| 客户问题跟踪 | Issue Tracking、重点客户跟踪、Customer Issue |

---

## 2. 产品线判定（tag1）— 基于 QT-SOP-PM-048E

项目名/模组名首字母与产品线对应关系（节选自命名规范 V12）：

| 产品线 (tag1) | 命名特征 | 常见型号族 |
|---------------|----------|------------|
| **Cellular** | 首字母 E/R/B/M/U/T + 封装字母（排除 Smart/Automotive） | EC/EG/BG/BC/RG/RM/EM/UC… |
| **Automotive** | 车载模组 / 毫米波雷达 | AG/AM… |
| **Smart** | 首字母 S | SC/SG/SP/SE/SH/SA… |
| **GNSS** | 首字母 L | LC/LG/LS/L76/L89/LUA… |
| **ShortRange** | 首字母 F/H/K | FC/FCM/HC/KC…（WiFi/BT/Zigbee/LoRa） |
| **Satellite** | 首字母 C 的卫星模组 | CC660/CC950…；正文含 NTN/D2C/Starlink |
| **Antenna** | 天线产品线 | 标题/正文以天线为主 |
| **QuecOpen** | 开放系统 SDK / 拨号 / 外设驱动开发 | 常叠加在 Cellular/Smart 模组上 |

### 2.1 裁决优先级（必须遵守）

1. **标题中出现的模组型号**所属产品线  
2. **正文中作为操作对象、提及次数最多**的模组型号所属产品线  
3. **来源 wiki 文件夹域**（ShortRange / Automotive / GNSS 等路径提示）  
4. LLM 对正文技术主题的语义判断（在已确定的 tag1 下选叶子）

实现模块：`classify/module_product_map.py`（正则 + 加权计分）→ 注入 LLM Prompt → 若结果为 `Others` 且已识别模组产品线，则强制在该产品线子树内重选；仍失败则落到该产品线默认叶子（禁止再回 Others）。型号匹配支持中文紧贴（如 `AG35模组`），并排除 `RGMII`/`eMMC` 等误报。

---

## 3. 叶子路径选择（tag2 / tag3）

在确定 tag1 后：

1. 必须落到标签树**最底层叶子**（不能停在 `Smart -> BSP`）  
2. 优先用关键词下钻（驱动、协议、接口等别名表 `REFINEMENT_ALIASES`）  
3. 仍不确定时二次调用 LLM，限定在候选叶子列表内选择  
4. 输出名称必须与标签树完全一致（大小写敏感）

标签树唯一数据源：`classify/llm_tree_classifier.py` 中的 `LABEL_TREE`。

## 4. Others 质量控制

| 配置项 | 默认 | 含义 |
|--------|------|------|
| `OTHERS_RATIO_FAIL_THRESHOLD` | `0.15` | 一次运行中，Others / 已分类文档数；超过则**告警并写报告**，仍继续复制 |

- **分母**：成功得到标签树路径的文档（不含排除类、不含分类 API 失败）  
- **分子**：`tag1 == Others` 的文档数  
- **超限行为**：继续复制；写入 `logs/others_ratio_report.json`（并同步一份 `others_ratio_failure.json` 兼容旧路径）  
- 设为 `0` 可关闭该告警  

设计意图：把「未精确分类占比」暴露出来便于复盘，同时不阻断主流程。

---

## 5. 目标目录单层节点超限（飞书 131003）

飞书知识库同一父节点下子节点数量有上限。当复制（或后续写入）返回：

```text
code=131003
msg=out of limit: The number of single-layer nodes in space has reached the upper limit
```

系统自动：

1. 在**同一父节点**下创建同类型分卷文件夹：`{原名} (2)`、`{原名} (3)`…  
2. 将**当前及后续**同类型文档改写入新文件夹  
3. 运行期内记住「活跃分卷」，避免反复撞上限  

示例：

```
TARGET / Others          ← 已满
TARGET / Others (2)      ← 自动创建，后续 Others 写入此处
TARGET / Cellular / Network / LTE Network
TARGET / Cellular / Network / LTE Network (2)  ← 叶子层满时同理
```

配置：`ENABLE_FOLDER_ROLLOVER=true`（默认开启）。  
实现：`state/folder_rollover.py` + `feishu/copy_doc.FeishuCopyError`。

---

## 6. 端到端流程（与分类相关）

```
扫描叶子 docx
  → [可选] 附件提取
  → 并行读取正文
  → 并行分类
        ├─ 排除类 → SKIP
        ├─ 模组/项目名计分 → 产品线提示
        ├─ LLM 选叶子路径
        └─ Others + 已识别产品线 → 域内重选
  → Others 占比检查（>15% 则告警写报告，仍继续复制）
  → 串行复制（超限则分卷）
```

---

## 7. 配置一览

```env
# Others 占比超过 15% 则告警写报告，仍继续复制（0=关闭告警）
OTHERS_RATIO_FAIL_THRESHOLD=0.15

# 单层节点超限时自动创建 名称 (2)/(3)…
ENABLE_FOLDER_ROLLOVER=true
```

相关代码：

| 路径 | 职责 |
|------|------|
| `classify/module_product_map.py` | QT-SOP-PM-048E 模组→产品线 |
| `classify/llm_tree_classifier.py` | 标签树、Prompt、域强制、排除类 |
| `state/folder_rollover.py` | 超限分卷 |

| `tools/reclassify_others_move.py` | Others 存量纠偏 |
| `main.py` | Others 占比门禁、复制编排 |

## 10. 存量 Others 纠偏（移动）

已复制进 `TARGET/Others`（及 `Others (2)`…）的文档，**不会**被 `main.py` 源目录重跑自动纠正。

使用专用脚本（**move，非 copy**）：

```powershell
# 先预览
python -m tools.reclassify_others_move --dry-run --max-documents 20

# 正式移动（存量纠偏可跳过 Others 占比门禁）
python -m tools.reclassify_others_move --skip-others-ratio-check
```

默认自动发现 `TARGET_PARENT_TOKEN` 下名为 `Others` / `Others (N)` 的文件夹；也可用 `--others-token` 指定。

报告：`logs/others_reclassify_move.json`

### 10.1 Others 主题归档（可选）

产品线纠偏后仍留在 `Others*` 的文档，可用主题子文件夹二次整理：

```powershell
python -m tools.others_theme_classify_move --dry-run
python -m tools.others_theme_classify_move
```

主题夹（开发与平台工具 / 测试与认证 / … / 杂项）**只创建在主 `Others` 下**；`Others (2)` 等次级夹中的文档会迁入主 Others 主题夹，尽量清空次级夹。

报告：`logs/others_theme_classify_move.json`

## 10.2 文档增强管道（贴表 + 附件分隔）

`main.py` 复制成功后调用 `enrichment` 管道（不堆逻辑进 main）。默认步骤：

1. **元数据表**：目标副本顶部「文档元数据」标题 + 两列表格  
2. **附件分隔符**：若存在 `附件：…` 标题且尚无横幅，在其前插入醒目分隔区

贴表字段约定（前 5 行为源数据，旧表需 `--force-metadata` 重贴）：

| 行 | 来源 |
|----|------|
| **原文档名称** | SCAN 源标题（共享库 `title` / 源节点 title；不随 TARGET 改名变化） |
| **源文档路径** | SCAN 目录 breadcrumb（经 `SHARED_STATE_DB`）；**不是**知识枢纽路径 |
| **作者** | 与展示标题相同：通讯录显示名；失败则 SCAN 人名文件夹（中英文都保留） |
| **产品线** | 分类 `tag1`；回填无 tag 时取 **分类路径** 第一段 |
| **源文档创建时间** | SCAN 源节点 `obj_create_time` |
| **文章主题** | 与展示标题相同：LLM 按正文归纳（`DISPLAY_TITLE_USE_LLM_PURPOSE`）；失败则规则回退 |
| 模块型号 / 文档类型 | 正则扫 PN；没有 PN 时 LLM 归纳主型号/产品；文档类型规则 + 可选 LLM |
| **分类路径** | 复制时用分类 `tag`；**回填**用 TARGET 目录面包屑（`target_path`） |
| 来源文件夹 | 源路径第一段 |

```env
ENABLE_METADATA_TABLE=true
METADATA_TABLE_FETCH_AUTHOR=true   # 需联系人只读；可关以加速
# 贴表列宽 px：标签列,值列（默认 160,560；飞书未指定时约 100px 易挤换行）
METADATA_TABLE_COLUMN_WIDTHS=160,560
ENABLE_ATTACHMENT_SEPARATOR=true
```

已复制旧文档（去重跳过）需回填；若旧表作者/路径错误，强制删表重贴：

```powershell
python -m tools.enrich_copied_docs --dry-run --limit 20
python -m tools.enrich_copied_docs
python -m tools.enrich_copied_docs --force-metadata --steps metadata_table
```

扩展新增强：在 `enrichment/steps.py` 增加 Step 并挂入 `default_steps()`，复制后与回填会一并生效。

## 10.3 文档元数据 → 多维表格（独立工具）

默认处理 TARGET 副本；字段与贴表对齐，并写出 **原文档名称、源文档路径、作者、产品线、源文档创建时间**（经 `SHARED_STATE_DB` 还原 SCAN 源）。已有表会自动补列。

```powershell
python -m tools.export_doc_metadata_bitable --all-assigned --mode per-token
python -m tools.export_doc_metadata_bitable --all-enabled --mode aggregated
```

三人并行建议先 `--mode per-token`，最后一人再跑汇总表。配置见 `.env.example` 中 `METADATA_BITABLE_*`。

报告：`logs/doc_metadata_bitable.json`

## 10.3.1 归纳新标题（多维表格 / 重命名 TARGET）

默认只处理 **`TARGET_PARENT_TOKEN` 下已分类复制的文档**。

格式：**`文章主题-模组型号-作者`**

| 段 | 规则 |
|----|------|
| 文章主题 | **根据正文**归纳这篇文章要说明/表达什么；禁止日期、流水号、照抄原标题（LLM，与贴表共用） |
| 模组型号 | ① 标题/正文正则扫到的模组 PN；② 否则 LLM 归纳本文主要针对的模组或产品名；③ 再否则 TARGET **一级\|二级** 目录名 |
| 作者 | 源路径人名文件夹若同时有中英文则都写入（如 吴恩荣·Natalie.Wu、梁波·Edwin Liang）；否则通讯录显示名，再回退文件夹单语人名 |

```powershell
python -m tools.export_display_title_bitable --dry-run --max-documents 20
python -m tools.rename_target_display_titles --dry-run --max-documents 20
python -m tools.rename_target_display_titles
```

控制台：运行页筛选 **「归纳新标题」**。

- **写入汇总表**：只写多维表格，不改 wiki 标题  
- **重命名 TARGET 副本标题**：按同一格式调用 wiki `update_title`，**只改 TARGET，禁止扫源**

配置：`TOOL_DOC_SCOPE`、`TOOL_OPS_DB`、`DISPLAY_TITLE_*`、`DISPLAY_TITLE_SKIP_EXISTING`、`DISPLAY_TITLE_RENAME_SKIP_EXISTING`、`METADATA_TABLE_FETCH_AUTHOR`。报告：`logs/display_title_bitable.json` / `logs/display_title_rename.json`。

## 10.3.2 源 → TARGET 内容刷新（单向、按需）

SCAN 与 TARGET 是独立副本，**不做双向同步**。源正文变更后若要跟进到知识枢纽：

1. 按 `SHARED_STATE_DB` 找到 `source → copied` 映射  
2. 若源 `obj_edit_time` 新于上次刷新（或当前副本时间），重拷到同一父目录  
3. **保留**当前 TARGET 整理标题  
4. 旧副本移入 `TARGET/_已废弃_源刷新`（飞书 wiki 无可靠删除 API）  
5. 更新共享库 `copied_node`；可选再跑 enrichment  

```powershell
python -m tools.refresh_target_from_source --dry-run --limit 20
python -m tools.refresh_target_from_source
python -m tools.refresh_target_from_source --force
```

控制台：运行页 **「运维纠偏」** → 源 → TARGET 内容刷新。配置：`REFRESH_TARGET_SKIP_UNCHANGED`、`REFRESH_TARGET_OBSOLETE_FOLDER`。

## 11. 多人并行分卷状态

活跃分卷写入共享库（默认与 `shared_copy_state.db` 同目录的 `folder_rollover_state.db`），避免各 worker 各自撞满 `Others`。

```env
ENABLE_FOLDER_ROLLOVER=true
# FOLDER_ROLLOVER_DB=\\HF-D-006494B\shared_db\folder_rollover_state.db
```
